# JCHK Data Journey and Resilience

JCHK investigations combine evidence about network communication with evidence from individual computers. Understanding where each kind of evidence originates and remains stored helps explain both normal operation and the consequences of failures.

## Three different outputs from one observed conversation

A **packet** is a unit of network data. **Packet capture (PCAP)** preserves captured packet bytes. **Metadata** records facts extracted from traffic, such as addresses, timestamps, protocols, and connection details. An **alert** records that a detection condition matched. A **protocol** is a set of rules devices use to communicate.

Imagine a workstation contacts an unfamiliar server. The packet capture may contain the actual exchanged bytes, subject to capture settings and encryption. A metadata record may state which addresses communicated, for how long, and using which protocol. An alert may say that the traffic matched a known suspicious pattern. These outputs complement each other: an alert points to something to examine, metadata helps scope it, and packet data can provide the underlying detail.

This example is explanatory, not an assertion that every connection generates all three outputs or that encrypted content becomes readable merely because it was captured.

## Network evidence path

1. **Production traffic reaches an observation point.** A production network is the partner network carrying real operational communications. An **inline TAP** is physically inserted into one link and copies the traffic for monitoring. Alternatively, a configured **SPAN** or mirror port sends copies from a switch. A switch mirror is a separate collection option, not another supplied TAP.
2. **Copies reach sensor monitoring ports.** A monitoring port is the sensor connection assigned to receive observed traffic. It serves a different purpose from its management or provisioning connection. The ASF01 exposes separate network-side and tool-side ports.
3. **The sensor produces evidence.** **Suricata** is the network detection engine used here for alerts and packet capture. **Zeek** creates structured descriptions of observed network activity. **Strelka** scans extracted files or artifacts; an **artifact** is an item of potential investigative interest, such as a transferred file.
4. **Evidence is stored or forwarded according to the sensor role.** The large SN 9000 is a Security Onion **Heavy Node** with local packet capture and local Elasticsearch indexing. The smaller SN 3100 is a **Forward Node**: local packet capture, with logs/metadata sent to central indexing components. **Elasticsearch** is the search and indexing engine used by these tools.
5. **Analysts query the evidence.** Central Security Onion interfaces and related applications let analysts investigate observations across the deployment. Remote queries depend on working connectivity to the relevant storage location.

The guide sometimes compresses this into “sensors forward metadata to analytics.” The platform-specific descriptions are more precise: the SN 9000 can retain and index metadata locally. Central visibility does not require every sensor to store the same thing in the same place.

## Endpoint evidence path

An **endpoint** is an individual computer or other end device. An **endpoint agent** is software installed on that device to collect events or carry out approved investigation tasks. A **host log** is a record of activity generated by the endpoint's operating system or applications.

The overview describes agents sending host logs through a Hunt Site firewall to analytics services. Security Onion Fleet manages Elastic Agent connections and log ingestion; Velociraptor supports endpoint monitoring, investigation, and digital forensics. **Digital forensics** examines digital evidence to establish what happened, when, and on which systems.

Mission-facing services reside in a **demilitarized zone (DMZ)**, a network segment used to separate externally reachable services from more trusted internal resources. The DMZ is a controlled access area, not a promise that all applications placed there are inherently safe. Firewall rules and application configuration still determine actual access.

## The management path is a third path

Investigative evidence is distinct from **management traffic**, which administers devices and services. Management may use web interfaces, **SSH** (Secure Shell, an encrypted remote terminal connection), or **IPMI** (Intelligent Platform Management Interface, a hardware-management interface). A server's IPMI controller can provide power control or a console even when its main operating system is not functioning.

That distinction is useful when diagnosing a fault. Successful access to a sensor's hardware-management page does not demonstrate that the capture software is ingesting packets. A working analyst web page does not demonstrate that every remote sensor is reachable. Each path must be evaluated independently.

## What remains available during an outage

**Resilience** means preserving useful function despite failures. **Autonomy** means a site can continue some work without another site. The sources state that Hunt Sites continue local packet capture and metadata generation when inter-site tunnels fail.

| Failure or limitation | What can continue | What cannot be assumed |
|---|---|---|
| Inter-site VPN unavailable | Local sensor capture and local evidence generation, while local prerequisites remain healthy | Remote access, current cross-site visibility, or immediate delivery of all metadata |
| Analyst workstation disconnected | Already available local files and local desktop analysis | Fresh server results or control of remote sensors |
| Central application unavailable | Independent sensor collection may continue | Central search, endpoint service availability, or automatic recovery of every application |
| Storage reaches retention limit | Behavior depends on capture/retention configuration | Indefinite preservation of old packet data |

The source does not specify unlimited buffering, exact replay behavior, or an evidence-retention guarantee through every failure. **Buffering** temporarily holds data awaiting processing or transmission. Packet files and metadata may have different storage policies and different histories after an outage. Reconnection therefore requires checking collection continuity and delivery, not only whether a tunnel indicator is green.
